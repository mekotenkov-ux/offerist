# Парсинг сайта для SEO аудита

Офферист включает настоящий [SiteOne Crawler](https://github.com/janreges/siteone-crawler), закреплённый [релиз v2.5.1](https://github.com/janreges/siteone-crawler/releases/tag/v2.5.1). Это отдельный нативный движок обхода и анализа, а не название для собственного urllib-парсера. Официальный Windows x64 ZIP размером 8.8 MB включён в `assets/siteone`; MIT LICENSE сохранена рядом. Источник, версия, SHA-256 архива и исполняемого файла находятся в `assets/siteone/runtime.json`.

## Запуск

```powershell
python scripts/siteone_audit.py --site https://example.org/ --out work/siteone-audit --max-pages 100 --max-depth 8 --seconds 180
```

Команда принимает любой установленный Python 3.10+. На Windows x64 дополнительные пакеты, PHP, WSL, Docker, установщики и действия пользователя не нужны. ZIP автоматически проверяется по SHA-256 и распаковывается в `.siteone-runtime` рядом с каталогом результата. Повторный запуск проверяет SHA исполняемого файла. Путь плагина и рабочий каталог могут содержать пробелы и кириллицу. На Windows ARM64 используется штатная эмуляция x64, если она доступна; отдельный ARM64 runtime не включён и не проверен. Linux и macOS этим поставленным runtime не поддерживаются.

Всегда задавай новый пустой `--out`. Скрипт не перезаписывает предыдущий сбор и использует новый HTTP cache, поэтому старые ответы не выдают себя за свежие. Для известного сопоставимого полного реестра можно добавить `--known-total 2400`. Число должно относиться к той же области и тем же типам URL. Если оно меньше реально посещённого количества, доля оставляется неизвестной.

Режим по умолчанию ограничен 100 URL, глубиной 8, 180 секундами, двумя worker и двумя запросами в секунду. Можно явно выбрать 1–1000 URL, глубину 1–20 и 15–900 секунд. Для КП используй ограниченный обход; больший аудит нужен только по масштабу задачи. В лимит посещённых URL SiteOne не входят вспомогательные запросы вроде robots.txt; параллельные запросы могут дать небольшое превышение числа URL. Фактический охват находится в отчёте.

Обход следует robots.txt, сохраняет проверку TLS, не исполняет JavaScript, не загружает изображения, скрипты, стили и документы. Не отправляет формы, не подключает AI-провайдеров, не использует браузерные cookies. Исключает типовые login/logout/cart/checkout и action URL. Не добавляет внешние домены в область обхода. В subprocess передаются только необходимые переменные окружения Windows, без локальных API ключей.

## Файлы результата

| Файл | Что подтверждает |
|---|---|
| `siteone.json` | Полный исходный отчёт настоящего движка с HTTP ответами, анализаторами и его оценками |
| `siteone.html` | Интерактивный отчёт SiteOne для человека |
| `http-cache/**/*.cache` | Первичные ответы, сохранённые самим SiteOne, с URL, статусом, заголовками и base64 HTML |
| `run.json` | Команда, закреплённый runtime, фактические начало, конец, длительность, exit code и timeout |
| `pages.csv` | Проверенные HTML, статус, title, H1, description, canonical, noindex, наблюдаемые входящие/исходящие ссылки, глубина, ссылка и SHA первичного ответа |
| `links.csv` | Все извлечённые из сохранённого HTML пары source → target, повторения ссылки, nofollow, пример анкора, внутренний/внешний тип и известный статус назначения |
| `graph.json` | Узлы и реальные внутренние рёбра, включая обнаруженные, но не посещённые узлы |
| `findings.csv` | Каждая проверка, число затронутых объектов, знаменатель, единица, процент и ограничение |
| `audit-summary.json` | Охват, ограничения, SEO оценка и все вышеперечисленные результаты для аналитика/визуализатора |

Повторно сайт для построения графа не скачивается. Нормализатор читает HTML из HTTP cache SiteOne. Это важно: штатная таблица 404 SiteOne показывает только один найденный источник для битого назначения. Для масштаба битых связей Офферист восстанавливает **все** пары source → target из всех реально сохранённых HTML. Две ссылки из разных страниц на один 404 — две связи; две одинаковые ссылки в одной странице — одна пара и два вхождения.

## Знаменатели и охват

`pageCount` — посещённые URL с ответом движка, `linkEdgeCount` — уникальные наблюдаемые внутренние направленные пары. В `coverage` отдельно указаны HTML ответы, успешные HTML, HTML без noindex, вхождения ссылок, проверенные связи и связи с неизвестным статусом. Нельзя подменять одно другим.

- Битые ссылки оцениваются среди уникальных связей с **известным HTTP статусом назначения**. Непосещённые назначения неизвестны, а не исправны.
- Missing/duplicate title, H1 и description оцениваются по HTML 2xx без наблюдаемого noindex. Это не доказательство реальной индексации Яндексом или Google.
- Noindex и отсутствие canonical показаны отдельно как объекты проверки намерения. Они не являются автоматическим основанием снять noindex или назначить self-canonical всем страницам.
- Дубликаты title считаются в затронутых страницах, а не в строках title или группах дублей.
- Inlinks, outlinks и глубина относятся к наблюдаемому графу. Это не измерение PageRank всего сайта. На частичном графе нельзя объявлять сиротами все страницы без входящих связей.

`scope` равен `bounded_sample` при достигнутом лимите, пропусках или обнаруженных непосещённых URL. Иначе это только `discovered_linked_component`. Полнота **всего сайта никогда не объявляется**: обход по ссылкам не видит настоящие сироты. Сопоставляй граф с sitemap, GSC и Вебмастером. Связный обход — не случайная репрезентативная выборка; процент ошибок нельзя механически умножать на весь сайт.

Если остановка по времени не оставила валидного `siteone.json`, скрипт возвращает ошибку, сохраняет первичные ответы и `run.json`, но не выдаёт успешный аудит. Начинай следующий сбор в новом каталоге. Не перезапускай уже идущий сбор только из-за timeout наблюдения процесса.

## Чек лист технической оценки

| Блок | Проверки | Источник и область |
|---|---|---|
| Доступность | HTTP 4xx/5xx, редиректы, сетевые ошибки, фактическая доля битых связей | Посещённые URL и наблюдаемые связи SiteOne |
| Доступность для поиска | robots.txt, пропуски обхода, meta/X-Robots noindex, canonical | Сохранённые HTML/headers и таблицы skipped; намерение подтверждается отдельно |
| Метаданные | Пропущенные и дублированные title/description, H1, несколько H1, иерархия заголовков | HTML и встроенные SEO/heading анализаторы SiteOne |
| Дубли и маршруты | Одинаковые title, неканонические адреса, цепочки редиректов, параметры | Наблюдаемые страницы и таблица redirects; не считать все совпадающие title дублями содержания |
| Перелинковка | Число входящих/исходящих связей, глубина, ссылки на ошибки, неизвестные назначения | Реальный граф, затем сравнение с внешним полным реестром URL |
| Скорость | Время HTTP ответа, медленные URL, размеры ответов, кэширование, сжатие | Только HTTP и SiteOne; не выдавать за CWV или полную браузерную загрузку |
| Разметка и качество HTML | Heading, lang, canonical, OpenGraph, структурные нарушения | Встроенные анализаторы SiteOne; applicability зависит от типа страницы |
| Проверка поисковиков | Индексация, исключения, sitemap, canonical в GSC и ошибки Вебмастера | Отдельные доступные GSC/Вебмастер инструменты; SiteOne их не подменяет |

JS rendering, валидность JS-only интерфейсов, картинки и их alt, внешние битые ссылки и Core Web Vitals в данном режиме не проверяются. Наличие таблицы accessibility/security не доказывает полноту этих направлений при отключённых ресурсах. Пользовательский технический раздел должен показывать состояния и масштабы, а не выдавать каждую служебную notice SiteOne за приоритетную SEO работу.

`seo_health` даёт три зоны — critical, serious, good — и отдельное unknown при недостатке данных. Это прозрачная оценка **наблюдаемой выборки**, а не поисковый рейтинг. Формула: 10 минус 3 × доля каждой критической проверки и 1.5 × доля каждой серьёзной проверки. Отдельные review пункты балл не снижают. Оригинальные оценки SiteOne сохранены отдельно: security/overall SiteOne не подменяют SEO состояние. В КП визуализируй три зоны, 3–5 самых масштабных фактов со знаменателями и покрытие; мелкие исправления оставь приложению.
