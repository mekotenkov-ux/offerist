# Решения по результатам исследования открытых репозиториев

Исследованы десять проектов; код не устанавливался и не копировался. README и видимый исходный код подтверждают устройство, но не качество генерируемых КП. Полный исследовательский отчёт хранится в проекте разработки.

| Решение для Оффериста | Где применяется | Полезный источник |
|---|---|---|
| Подтверждённые слова клиента отдельно от исследования и предложений подрядчика | intake, setup, seller; источник значимых условий | [Anthropic proposal-builder](https://github.com/anthropics/knowledge-work-plugins/blob/main/small-business/skills/proposal-builder/SKILL.md), Apache-2.0 |
| Один владелец документа, этапы возвращают самостоятельные результаты | seller и stage-plan; изменение проходит через одного автора | [Meraki ai-proposal](https://github.com/meraki-digital/ai-proposal), MIT; [DocForge](https://github.com/yoligehude14753/docforge), MIT |
| Подтверждённая цена и арифметика отдельно от текста модели | estimate, профиль pricing и calculate | [ai-proposal-generator](https://github.com/Shcherbin96/ai-proposal-generator), MIT |
| Каждая существенная претензия имеет место, доказательство и условие исправления | Доёбчивый клиент, review.json | [OpenRFP](https://github.com/CopelandBEC/openrfp), MIT; [proposal-ops-judges](https://github.com/JdeGraftJohnson/proposal-ops-judges), MIT |
| Техническая квитанция и содержательное ревью — разные проверки | check не присваивает качество; отдельный fresh client | Те же оценщики, адаптировано без их многоагентного стека |
| Экспорт из актуального текста, приватные заметки отдельно | client-packet с хешами, optional presentation | Anthropic proposal-builder; ai-proposal-generator |

В ядре достаточно brief, evidence, результатов выбранных стадий, единого proposal и review. Не добавлены отдельная база proposal_state, векторная БД, биллинг, электронная подпись или 21 судья. Внутренние заметки продавца не передаются Клиенту: он получает лишь настоящий клиентский пакет. Разделы и сроки не обязаны браться из фиксированного каталога — агент может предложить их с обоснованием; актуальные ставки и коммерческие обещания не выдумываются.

Сходство текста с найденным фрагментом не доказывает факт. Обязательный сложный граф не нужен: источник и связь с решением фиксируются для существенных утверждений. Для blind-тестов разработческий builder проверяет заявленное происхождение и локальный карантин; это не изоляция файловой системы и не автоматическое определение правдивости любого нового источника.

Открытые репозитории с неясной лицензией или AGPL-кодом не включены в дистрибутив. Здесь используются самостоятельно сформулированные архитектурные решения и ссылки, не перенесённая реализация. Проверено 25.09.2026.
