# Необязательные локальные сборщики

Ядро может пользоваться подходящими доступными инструментами. Эти помощники нужны, когда удобен воспроизводимый локальный сбор. Python 3.10+; для GSC нужен Node.js и OAuth-клиент. `--help` каждого скрипта показывает актуальные параметры.

- `scripts/connectors/internal/collector.py` — выбор сайта в доступных GSC, Метрике и Вебмастере, общий кэш и сбор отчётов.
- `scripts/connectors/internal/gsc_bridge.mjs` — GSC Search Analytics с пагинацией. Исчерпание API не означает все строки сайта.
- `scripts/connectors/internal/metrika_bridge.py` — счётчики и отчёты Метрики с пагинацией и семплированием.
- `scripts/connectors/internal/wm_bridge.py` — отчёты Вебмастера; provider-limited popular queries остаются ограниченной выборкой.
- `scripts/connectors/external.py` — Keys.so страницы/ключи с полной пагинацией; Ahrefs metrics/backlinks-stats агрегаты с явным бюджетом.

## Сначала обнаружь доступы

Секреты не входят в плагин. До просьбы о ключе или вывода «нет доступа» прочитай локальные AGENTS.md и несекретный реестр `CODEX_CONNECTIONS_REGISTRY` (Windows User либо process); обычный путь — `%LOCALAPPDATA%/SEOMEAT/connections/registry.json`. Реестр перечисляет известные подключения, но не является исчерпывающим списком. Запусти `python <корень-плагина>/scripts/connectors/connections.py`: он показывает только имена служб, статус чтения реестра и наличие XMLRiver, без сетевых вызовов и значений ключей. `permission_denied` требует обычного scoped escalation, а не вывода об отсутствии подключения. Не меняй ACL и sandbox.

Для зарегистрированных GSC/GA4/Yandex/Keys.so/Ahrefs загрузи только нужную службу: `. <папка-connections>/Use-Connections.ps1 -Service gsc|ga4|yandex|keysso|ahrefs`. `-Status` проверяет метаданные, не API. Для GA4 отдельно получи properties через `native_cli` реестра, выбери фактическое свойство клиента и передавай `--property` каждому ресурсному запросу; GSC property не определяет GA4 ID. Проверь properties и небольшой отчёт для разрешённого сайта. Для Метрики явно выбери фактический counter по домену. Managed MCP используй через родные tools.

Явно выбирай разрешённый сайт/counter/property. Общий доступ к аккаунту не разрешает анализировать все его сайты. Не показывай токены, env-файлы, Authorization, cookies и URL с ключами в выводе или отчёте.

В отчёте Keys.so используй возвращаемый `search_context` (система и город) вместе с `base`; это контекст базы, а не текущая местная выдача. По [контракту провайдера](https://apidoc.keys.so/) `gru` — Google **Москва**, `msk` — Яндекс Москва. Не расширяй их до всей России. Дата получения отчёта не является датой SERP.

## XMLRiver без повторной настройки

Для SERP используй готовый `scripts/connectors/xmlriver.py`, а не новый одноразовый HTTP-код. Пример: `python <корень-плагина>/scripts/connectors/xmlriver.py --engine yandex --query "<запрос клиента>" --region-id 54 --region-name "Екатеринбург" --cache-root <новый-кэш-КП>/xmlriver --max-attempts 40 --live --output <отчёт>.json`. Google требует свой `--region-id` (loc), а не ID Яндекса. Общий предел относится ко всем запросам и системам в одном cache-root. По умолчанию до четырёх попыток на запрос, все входят в общий предел. Сборщик ждёт ответ до65секунд, повторяет временные 110/111/115/202/203/500 с паузой, сохраняет успешную органику и явно отделяет ошибку/пустой результат. Ошибка параметров не повторяется вслепую. Сохранённые `retrieved_utc` и регион относятся именно к этому съёму; `cache=true` означает повторное чтение, а не новую выдачу. Предел попыток зафиксируй до первого вызова.

XMLRiver может отсутствовать в общем реестре. Проверяй `XMLRIVER_USER_ID` + `XMLRIVER_KEY`, затем совместимый `XMLRIVER_API` в формате `user:key`, в текущем процессе и Windows User. [Помощник подключений](../scripts/connectors/connections.py) возвращает `xmlriver_credentials()` только вызывающему коду в памяти; его CLI выводит лишь boolean. Если пользователь или локальная инструкция указали отдельный private env-файл, поддержан `--xmlriver-env-file`; загружаются только эти три имени. Не ищи ключи массовым сканированием каталогов и не запускай целиком загрузчик чужого проекта ради XMLRiver. Отсутствие переменных после этих проверок — конкретная лакуна; уже найденный ключ повторно не спрашивай.

Различай продукты: SERP Яндекса/Google даёт позиции и конкурентные URL; Wordstat New даёт спрос. [Live parser Яндекса](https://xmlriver.com/apiydoc/apiy-about/) (`/search_yandex/xml`, `groupby=10`) и [Yandex Search API](https://xmlriver.com/apiysearch/apiys-params/) (`/yandex/xml`, составной `groupby`) — разные сервисы и контракты. Для обоих задавай `query`, явный `lr` нужного города, `device`, страницу от 0; для Search API также `format=xml`. Не переключай endpoint вслепую после ошибки: проверь контракт/доступ и оставшийся бюджет. [Google](https://xmlriver.com/apidoc/api-about/) использует собственный `loc`, `country`, первая страница — 1; язык или страна сами не задают город. Не подменяй локальные позиции московской базой и не выдавай отсутствие домена в TOP-N за точную позицию ниже N. [Wordstat New](https://xmlriver.com/apiwordstatnew/apiwn-about/) использует `regions`, `pagetype=words|history`; частоты и SERP-счётчики не взаимозаменяемы. Пустая выдача фраз не означает нулевую частоту.

Применяй XMLRiver для конкретной лакуны, которая меняет выбор страниц/конкурентов, в разрешённом регионе. До сети зафиксируй вопрос, список/охват запросов и небольшой предел попыток; не снимай всё ядро по факту наличия ключа. Переиспользуй общий cache-root и ledger текущего КП: резервируй попытку **до** запроса под общей блокировкой, учитывай таймауты/ошибки и повторы, не обнуляй бюджет сменой папки. Кэш-ключ строится из параметров без авторизации. Не сохраняй полные request URL, исключения `str(exc)` или необработанный аккаунтный ответ: они могут содержать ключ. Для `get_info` допускай только нужные числовые поля balance/cost/threads/engine; наличие ключа само по себе не требует запроса аккаунта. Если нужен вызов, он также входит в предел попыток. Сохраняй безопасный код ошибки и параметры без user/key; не выводи сырой ответ до проверки. Личные значения и клиентские данные не включаются в дистрибутив.

Для GSC после `. Use-Connections.ps1 -Service gsc` сборщик принимает `GSC_OAUTH_CLIENT_FILE` и `GSC_TOKEN_FILE` из текущего процесса. Явные `--gsc-client-file` и `--gsc-token-file` имеют приоритет. Прямой `gsc_bridge.mjs` принимает те же переменные или явные `--client-file`/`--token-file`; в обоих режимах нужен `--site` с точным разрешённым свойством. Старые пути `.secrets` не используются. Запросы обновления токена через мост сериализуются файловой блокировкой.

Коды GSC следует трактовать отдельно от данных: `refresh_token_expired` означает истечение по сохранённой дате и не вызывает OAuth-запрос; `oauth_invalid_grant` и `oauth_http_400` означают сбой OAuth, но сами по себе не доказывают конкретную причину. `gsc_http_401/403/404` — коды ответа API; 403 может быть связан с правами, а 404 или `gsc_site_not_listed` — с неверным свойством или недоступным сайтом, но для вывода нужна проверка точного свойства и доступа. `gsc_credentials_unavailable` и `provider_error` означают недоступный источник. Успешный пустой ответ (`rows: []`, `api_exhausted: true`) означает отсутствие видимых строк в выбранном срезе, а не отсутствие органического трафика всего сайта. Ошибка первой страницы не превращается в пустой отчёт; ошибка после части страниц сохраняет их с `stop_reason: provider_error` и безопасным кодом причины.

Помощники работают с кэшем относительно рабочей папки `.offerist/cache`, а не внутри установленного плагина. Кэш и журнал сохраняются при переустановке. Старые обрезанные ответы не становятся полной аналитикой: новая схема либо отделяет их, либо явно обозначает охват. Ошибки посреди пагинации сохраняют успешно собранную часть как partial. Для большого отчёта сначала определяй нужный срез; все строки выбранного среза и все сайты аккаунта — разные задачи.

Для Keys.so `--per-page` — размер одного запроса, `--max-rows` — явно выбранный неполный предпросмотр. `--output` сохраняет общую выгрузку со всеми строками; без него сборка сохраняется в `.offerist/cache/external/reports` с уникальной датой. Консоль выводит только метаданные, путь и SHA-256. Для Ahrefs нужен явный `--ahrefs-max-requests`; его журнал сохраняй между запусками, ошибки тоже расходуют число попыток. `--ahrefs-budget-units` дополнительно ограничивает известный расход единиц; неизвестная тарификация не означает бесплатный вызов. Не загружай большие backlinks/keywords. В КП покажи источник, период и существенное ограничение, а технические offsets, JSON и SHA-256 оставь в приложении.

`collector.py collect` собирает базовые поисковые отчёты. Этот набор не заменяет техническую диагностику GSC/Вебмастера: этап audit отдельно получает нужные отчёты ошибок и индексирования через доступный инструмент, API или экспорт. Успешный сбор базовых отчётов не означает выполненный аудит.

Лимит попыток Ahrefs относится к суммарному журналу выбранного cache-root, не обнуляется при повторном запуске. Если нужно расширить бюджет, учти уже записанные попытки и разрешённое добавление; не обходи журнал сменой папки. Неизвестный расход единиц укажи отдельно.
