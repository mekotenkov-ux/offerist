# Протокол GEO измерения

## Матрица

Выбирай небольшую репрезентативную выборку небрендовых вопросов по важным интентам. Брендовые вопросы держи отдельно как диагностический контроль. Для каждого вопроса записывай исходную формулировку, систему (Яндекс AI ответ, Google AI Overview/режим, ChatGPT с указанием web search), язык, регион/местоположение, устройство, дату/время, состояние авторизации и персонализации, число повторов. Доступность фич зависит от региона/аккаунта; фиксируй фактический режим.

Состояния попытки: `answer`, `no_answer`, `no_sources`, `error`, `not_measured`. Для `answer` фиксируй текст/HTML, реальные citations, бренд в теле ответа и снимок. `no_answer` входит в число валидных запусков, но не в знаменатель доли цитирования *среди ответов*; поэтому показывай отдельно `ответы / валидные запуски`, `цитаты / ответы` и при необходимости `цитаты / валидные запуски`. Ошибку и неизмеренное не превращай в ноль. Для конкурентов используй тот же набор вопросов и условия.

Слои свидетельств: `retrieval/search_results` — URL среди кандидатов; `source` — URL в итоговых источниках; `inline citation` — URL, привязанный к части ответа; `brand mention` — имя бренда в тексте ответа. Сохраняй оригинальные URL и нормализованный домен отдельно. Не восстанавливай retrieval из списка цитат. Если интерфейс не раскрывает слой, значение `unknown`.

Ручной browser fallback: пройти вопрос в каждой системе, сохранить screenshot без дорисовки, скопировать видимый ответ и ссылки, зафиксировать контекст. Скриншот интерфейса подтверждает только видимое на нем и конкретный запуск, а не устойчивую долю видимости. Не создавай декоративный mockup, похожий на интерфейс системы.

Рекомендацию привязывай к конкретному вопросу, странице и разрыву: отсутствие в retrieval → релевантность/доступность/позиции; retrieval без цитаты → пригодность ответного фрагмента; цитата без бренда → проверка представления бренда на цитируемой странице. Это рабочие гипотезы, которые требуют повторного замера после правки.
