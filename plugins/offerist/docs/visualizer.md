# Локальная визуализация КП

Выбран [dom-to-svg](https://github.com/felixfbecker/dom-to-svg) 0.12.2 с лицензией MIT. Он превращает рассчитанную браузером раскладку HTML в SVG с векторными объектами и текстом без foreignObject. Применяется к собственным схемам и матрицам. Страница целиком не становится растровой картинкой внутри SVG. Рендерер создаёт PNG из полученного SVG для совместимой вставки в Word и Google Docs.

Сравнены открытые варианты. [html-to-image](https://github.com/bubkoo/html-to-image) 1.11.13 MIT использует foreignObject, поэтому хуже подходит как переносимый векторный исходник. [Satori](https://github.com/vercel/satori) MPL-2.0 поддерживает свой поднабор HTML/CSS и отдельный движок раскладки; его пришлось бы добавлять вместе со шрифтами и зависимостями. В этой среде уже есть Chromium и Playwright, поэтому выбран небольшой dom-to-svg без установки нового браузера. Это инженерный выбор для текущей среды, а не утверждение об универсальной точности экспорта любого сайта.

## Запуск

```text
node <plugin>/scripts/visualizer.mjs --input <run>/section.html --meta <run>/section.json --output <run>/visuals/section
```

Node и `node_modules` получи через `load_workspace_dependencies`. По умолчанию поиск Playwright идёт рядом с bundled Node; нестандартный путь задаётся `--modules-root`. Browser выбирается из `--browser`, `OFFERIST_BROWSER`, Playwright runtime либо установленного Chrome/Edge/Chromium. Отсутствующий браузер не скачивается автоматически. Создаётся отдельный временный контекст, существующие окна и профили пользователя не используются. Все сетевые запросы заблокированы. Шрифты Arial должны присутствовать в системе; PNG переносит уже отрисованную кириллицу без зависимости от шрифтов получателя.

Google Docs оформляется нативно по актуальному подключённому навыку `google-docs`: создание нового документа или копия шаблона, вставка изображения штатным инструментом, readback и визуальная проверка экспортированного PDF. Не навязывай DOCX-конвертацию для нового Google Doc. Word остаётся отдельным поддержанным выходом по запросу пользователя.

Встроенный browser bundle и полный набор лицензий лежат в `skills/offerist-visualizer/assets`. `renderer.json` фиксирует пакет, исходный npm tarball с integrity, версии сборки и SHA-256 bundle. Для работы нового КП сеть и установка npm не нужны. esbuild нужен только для воспроизводимой пересборки vendor-файла, не для запуска.

SVG и PNG следует проверять на конкретных макетах. Используй обычный текст, границы, блоки и таблицы; сложные фильтры, canvas, графику из JavaScript и внешние CSS сначала преобразуй в простой локальный макет. Настоящие образцы работ сохраняют свой источник и не выдаются за результат текущего клиента. Существующие `charts.py` и `reference_assets.py` сохранены.

## Сборка vendor-файла

В отдельной рабочей папке установи зафиксированные зависимости из `assets/renderer-build/package.json` с `pnpm install --frozen-lockfile --ignore-scripts`, затем выполни `node build.mjs`. Это выпускная операция, а не стадия каждого КП. Лицензии транзитивных пакетов сохранены в `THIRD_PARTY_NOTICES.txt`. При обновлении пересобери bundle, обнови его хеш, заново проверь русский макет, PNG и вставку в документ.
