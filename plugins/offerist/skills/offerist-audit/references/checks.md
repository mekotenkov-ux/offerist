# Технические проверки

1. Для реально использованных GSC/Вебмастера укажи точное свойство, доступные отчёты и дату. Недоступный источник и оставшиеся непроверенные вопросы перечисли отдельно; отсутствие доступа не означает ноль ошибок. Успешный discovery не доказывает доступ к диагностике.
2. Раздели performance (клики/показы/позиции), индексирование и технические состояния. Поисковая статистика GSC не заменяет отчёты об индексировании или URL Inspection. Если эти отчёты недоступны, это отдельный пробел.
3. В GSC используй доступные сигналы индексирования, sitemap и осмотр важных URL. В Вебмастере — диагностику, сводку, исключения, события и обход. Обязательно проверяй дату и смысл счётчика: старый пример 404 не доказывает нынешнюю ошибку; число исключений не равно числу проблем.
4. Проверь важные URL публично: HTTP-статус, цепь редиректа, canonical, robots, sitemap, ссылки, title/description/H1 и назначение страницы. Для спорного вывода нужен конкретный пример или честно неизвестный масштаб.
   Для каждого адресного ответа сохрани две разные сущности: `logical_key` для join с inventory и `request_url` — буквально переданный API ресурс. Сохрани исходный HTML/HTTP receipt, SHA-256, ответ и время. Отличающийся слеш, регистр, percent-encoding, query или fragment образует отдельный диагностический адрес; результат нельзя переносить на canonical. Отсутствующий canonical не восстанавливай эвристическим добавлением слеша. Cross-host canonical сначала согласуй отдельно.
5. SF — по нужным выгрузкам Internal, Response Codes, Canonicals, Directives, Inlinks, Page Titles/H1. Указывай настройки, дату, охват, JS rendering, исключения. Выборочный list-mode не равен полному краулу или индексу поисковика.
6. Сохрани реальные экраны, если интерфейс доступен. API-выгрузку не называй скриншотом; отсутствие картинки обозначь отдельно от доступности данных.

Карточка: `находка → URL/охват → доказательство/дата → последствие → конкретная правка → приоритет → проверка после внедрения → ограничение`. Не ставь «исправить все 404» без разбора назначения URL и внутренних ссылок.

Трафик, CTR как показатель поведения в выдаче, продолжение изучения и цели анализирует [offerist-analytics](../../offerist-analytics/SKILL.md). Технический специалист передаёт туда относящиеся к вопросу наблюдения, не повторяя полный анализ.
