# Протокол исследования

## Выбрать минимальный набор

| Вопрос | Предпочтительное свидетельство | Fallback |
|---|---|---|
| Что уже получает сайт | GSC: query/page, clicks, impressions, CTR, position; одинаковые периоды | Экспорт клиента; публичная видимость с пометкой «оценка» |
| Где конкурентный спрос | Keys.so для нужной базы Яндекса; DataForSEO/Keys.so/Ahrefs для нужной системы и региона | Sitemap/index, навигация и страницы конкурентов: структурный GAP без измеренного спроса/рангов; [правила](../../offerist-gap/references/external-gap.md) |
| Какие страницы дают результат | Страницы и запросы клиента + конкурентные URL, интент, структура | Ручная выборка URL с обозначенным охватом |
| Нужна ли ссылочная работа | Ahrefs: referring domains, тип/качество, динамика, пересечения | Открытые ссылки как примеры, без количественного вывода о профиле |
| GEO/AEO | Включить только по задаче; применять offerist-geo | Не делать GEO вывод |

API/MCP/экспорт взаимозаменяемы только на уровне *вопроса*, а не чисел. Актуальные пути API, цены, лимиты и поля проверяй по документации провайдера и ответу текущего запуска; учебные архивы — ориентир, а не действующий контракт.

## Журнал и сравнение

В журнале строки: `предлагаемое улучшение | исследовательский вопрос | источник | дата запуска | вход (без секретов) | рынок/регион/устройство | период | охват/лимит | результат/путь | статус | ограничение`. Секреты не помещай в артефакты.

Для сравнения доменов укажи поисковую систему, тип домена/URL, регион, дату базы, устройство, порог позиций и один и тот же набор кластеров. При несовпадении параметров показывай два отдельных среза. Числа `crawl`, `index` и `ranking_urls` живут в разных колонках; для каждого укажи источник, пагинацию, охват, способ canonical dedup и является ли число полным в данном срезе. Список 12 URL или topN не доказывает полноту. GSC скрывает часть низкочастотных запросов; сумма строк query может быть меньше итогов page. Не выводи точный размер рынка из видимой выборки.

Метрика, GSC и Вебмастер оформляются по API/экспорту [графиками Оффериста](../../offerist-charts/SKILL.md) и таблицами; снимки панелей не нужны. Для полезных скриншотов других инструментов сохрани исходный файл, URL/экран, время, устройство/регион и короткую подпись «что видно». Обрезка допустима, если сохраняет контекст и не меняет смысл. По тексту/JSON строй собственный график с источником, не макет «скриншота».

## Минимальная конкурентная таблица

Для клиента и согласованных конкурентов собери доступные видимость/топ-запросы, число всех страниц в сопоставимом продуктовом/региональном scope, уникальные ранжирующиеся URL, живые referring domains и живые ссылки. URL с рангом — distinct canonical URL, а не число строк query × URL; count охватывает только видимую базу и её порог. Для ссылок сравнивай один provider/date/scope и проверяй релевантность, качество, тип и динамику. Число уникальных доменов и число ссылок — разные единицы; арифметическая дельта доменов не равна заказу на ссылки. Укажи неизвестное и причину, не подменяй отсутствующее нулём. Данные открытых Ahrefs/Keys.so имеют собственный охват и дату. Приоритет глубины — по связи с целями клиента. Просмотри скрины инструментов, сопоставь одинаковые срезы клиента и конкурента, объясни вывод. [Единая карточка evidence](../../offerist/references/runtime.md).
