# Презентация КП

До текста слайдов прочитай [правила языка и хуманизации](../offerist-quick/references/client-language.md). Применяй к заголовкам, таблицам, подписям и схемам; сокращение сохраняет текущее состояние, оценку, факты и существенные ограничения исходного анализа.

Сначала проверь, попросил ли пользователь презентацию, слайды, PDF deck или визуальное КП. Если нет — отдавай ясный текстовый оффер. Для слайдов бери только уже проверенные тезисы, числа и реальные изображения из исследования; не расширяй обещания при переводе в визуальный формат. Цели клиента задают сюжет и критерий отбора слайдов.

Сюжет: предлагаемое улучшение показателей (или подтверждённая цель клиента) → препятствие и подтверждённый разрыв/возможность → конкретное решение и механизм влияния → этапы и результат каждого этапа → кто отвечает за внедрение и какие есть зависимости → проверка результата → смета ближе к концу → один следующий шаг. Один главный вывод на слайд; график получает явный бизнес-вывод, число — источник/период. Если нет данных, обозначь гипотезу. Позиции и трафик показывай как промежуточные сигналы, если оцениваемый результат шире.

Если выбран HTML/PDF, используй существующую дизайн-систему проекта только в соответствующем проекте и рендери финальные страницы перед выдачей. Для переносимого комплекта не копируй большой runtime и чужие шаблоны; достаточно сюжетного контракта. Скриншоты продукта/выдачи — только настоящие, с подписью; схемы и диаграммы можно строить как самостоятельные иллюстрации без имитации экрана.

Структура, плотность и проверка: [references/deck.md](references/deck.md). Источники: [происхождение методик](../../docs/sources.md).
