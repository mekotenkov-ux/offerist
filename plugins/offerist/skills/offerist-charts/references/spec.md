# Спецификация графика

Все типы принимают один JSON. Числа — JSON numbers, пропуски — `null`, не строки. Никаких сетевых запросов.

```json
{
  "type": "bar",
  "title": "Органические визиты по сопоставимым периодам",
  "metric": "Визиты",
  "unit": "count",
  "labels": ["Предыдущие 28 дней", "Текущие 28 дней"],
  "series": [{"name": "Поисковые системы", "values": [100, 120]}],
  "source": "Яндекс Метрика, API",
  "captured_at": "2026-09-28T10:00:00+03:00",
  "period": "01–28 августа / 01–28 сентября 2026",
  "filters": "example.org; поисковый трафик; все устройства; часовой пояс UTC+3",
  "definition": "Число визитов из органического поиска в каждом 28-дневном окне",
  "limitation": "Демонстрационный пример; не данные клиента",
  "derivation": "Пример входной структуры, не использовать значения в КП",
  "sample": true
}
```

В настоящем графике убери `sample` и укажи:
`"source_data": {"path": "exports/visits.csv", "sha256": "реальный SHA-256 файла"}`.
Путь разрешается относительно папки спецификации, может быть абсолютным. Генератор проверяет файл и хеш. Не передавай env-файлы, токены или выгрузки персональных данных как источник. Ввод — минимальный разрешённый срез аналитики; спецификация и квитанция не являются средством очистки секретов.

| Поле / тип | Условия |
|---|---|
| `line` | От трёх строго упорядоченных уникальных ISO-дат `YYYY-MM-DD`; координаты учитывают расстояние между датами, пропуск разрывает линию |
| `bar` | Любое число категорий и сопоставимых рядов; числовые подписи; для двух периодов предпочтительный тип. При плотной раскладке рендерер выбирает горизонтальные группы |
| `hbar` | Горизонтальные группы для названий страниц/конкурентов; неизвестное явно подписано |
| `stacked` | Любое число категорий и частей; `parts_exclusive: true`, `totals: [...]`; все части известны и сумма совпадает с итогом; только additive count/number. При плотной раскладке отображается горизонтально |
| `unit: count` | Неотрицательные целые |
| `unit: number` | Неотрицательные конечные числа, например средняя позиция; её улучшение означает уменьшение, объясни это в тексте |
| `unit: percent` | 0–100, подпись `%` |
| `unit: ratio` | 0–1, отображение умножает на 100 и добавляет `%` |
| Текстовые поля | Непустые строки без лимита длины. Длинные подписи и метаданные продолжаются на отдельных листах описания; исходные строки целиком остаются в `spec` квитанции |

Количество точек, категорий и рядов не ограничено контрактом. Генератор делит плотные графики на несколько PNG/SVG, чтобы каждый растр оставался умеренного размера. Все файлы перечислены в `outputs` и `panels` квитанции; `panels[].labels` и `panels[].series` содержат индексы исходных данных, а `kind: notes` обозначает лист с полными длинными подписями. Поле `rendered_type` фиксирует фактическую форму (`bar` может стать `hbar`, `stacked` — `hstacked`). Возвращённые `png` и `svg` указывают на первый лист; для КП просматривай и сохраняй все листы. Одинаковый цвет ряда повторяется по палитре после восьмого ряда, поэтому при большом числе рядов ориентируйся также на легенду и отдельные панели.

Все величинные шкалы начинаются с нуля. Второй оси, прогнозной интерполяции, автоматической склейки источников и расчёта рыночной доли нет. Если сравнение требует разных определений/единиц, делай отдельные графики. Для excluded URL, ошибок, целей и распределения работ нужны точные определения групп и базы; их смысл не устанавливает рендерер.

Типы выбраны по [официальному описанию графиков Метрики](https://yandex.ru/support/metrica/ru/reports/report-general). Палитра и оформление Оффериста вдохновлены аналитическим интерфейсом, не являются официальным экспортом Яндекса.
