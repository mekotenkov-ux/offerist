# Эталонное оформление

Этот документ описывает прежние варианты Word и применяется по явному запросу старого оформления. Новое полное КП следует [фиксированному шаблону](fixed-template.md): Google Docs и Word собираются из одного `proposal.json` v2 по [командам актуального маршрута](fixed-template-tools.md). У `build_docx.py` есть прямой JSON-вход с `--visual-dir`; он использует общую модель документа без Markdown. Ниже описан только прежний Markdown-режим, который не является маршрутом нового фиксированного КП.

Публичный визуальный образец — [синтетический DOCX](../assets/reference-proposal.docx). Он показывает прежнюю форму, а текущие каркас и содержание определяет шаблон v2. Частные клиентские оригиналы не входят в открытый комплект. Имена прежних стилей ниже сохранены как параметры совместимости сборщика.

## Два самостоятельных варианта

Не смешивай палитру и заголовки двух образцов в случайный третий стиль. Если пользователь не выбрал вариант, используй Woodcort. Посмотри титул, страницу с таблицей, выводом и графиком выбранного DOCX; метрики ниже уже извлечены из реальных стилей и проверены по PDF.

| Элемент | Woodcort | Antropik |
|---|---|---|
| Основной текст | Helvetica Neue 11–11,5 pt в фактическом тексте; в сборщике 11,5 pt, интервал после абзаца 8 pt | Helvetica Neue 12 pt в фактических runs, даже если named style сообщает Arial 11 |
| Заголовки 1/2/3 | 28/20/15 pt, чёрные, жирные | 30/22/16 pt, navy #1F2945, третий уровень rust #A1633B |
| Отступы до/после заголовков | 18/18, 18/10, 18/10 pt | 20/30, 50/20, 35/16 pt |
| Обложка | По центру, крупный жирный заголовок 37 pt, подзаголовок 21 pt, агентство и дата ниже | По центру, тёмно-синий заголовок 50 pt, пояснение 20 pt, тёплые блоки показателей |
| Таблицы | Голубая шапка #D9EAF7, чёрный текст, тонкая серая сетка | Шапка #1F2A44 с белым текстом, светлые/тёплые строки #F7F1EA |
| Вывод | Жёлтая плашка #FFF2CC с рамкой #D6B656; главный вывод зелёный #D9EAD3 | Зелёная плашка #E3EFDC с левой полосой #6AA84F |
| Фон | #F3F3F3 | #EFEFEF |
| Геометрия печати | A4, поля 72 pt | A4, поля 72 pt |

Исходные Google Docs **бесстраничные**. Их экспорт даёт 24 и 44 страницы из-за автопагинации; это не требование к объёму нового КП. Для печатного Word используй связный поток текста; разрывы добавляй только по необходимости и проверяй читабельность. Это аналитический документ, не презентация с одной мыслью на каждой странице. Не копируй разрыв слова на обложке или неудачный перенос таблицы только потому, что он возник при экспорте Google.

Helvetica Neue не входит в Windows-окружение этой установки; сборщик явно использует Arial как близкую замену. Не обещай точного совпадения метрик недоступного шрифта. Если шрифт установлен и разрешён для использования, применяй его и повтори рендер. Замена записывается во внутренней проверке, не в клиентском тексте.

## Сборка без новой разработки вёрстки

Сохрани `proposal.md` и используемые PNG/JPEG в его папке. Запусти поставляемый сборщик штатным Python окружения:

```text
python <путь-навыка>/scripts/build_docx.py --input <папка>/proposal.md --output <папка>/КП.docx --style woodcort
```

Для второго варианта передай `--style antropik`. Выходной файл должен быть новым. Поддерживаются заголовки, абзацы, полужирный/курсив, ссылки, плоские списки, таблицы, отдельные локальные изображения и `<!-- pagebreak -->`. Плашку вывода задавай блоком `>`. Неподдержанный синтаксис исправь по сообщению сборщика; не переписывай генератор для каждого клиента.

Один смысловой блок — понятный заголовок, короткое объяснение, подходящий показ решения и вывод; он не обязан занимать отдельную страницу или содержать таблицу. Применяй [правила простых клиентских таблиц](reference-storytelling.md#простые-клиентские-таблицы): обычно 2–4 колонки с одним вопросом, числовое сравнение до пяти, пустая человеческая смета может иметь шесть. Подробные URL-реестры и расчёты остаются в приложении. Не уменьшай шрифт ради широкой матрицы и не заполняй разделы общими SEO-обещаниями ради длины. Полный текст, таблицы, подписи и источники должны читаться без чата.

Создавай чистый документ, не заменяй домен в чужом образце. Перенос формы не переносит цены, коэффициенты, кейсы, реквизиты и обещания. Не удаляй существенные ограничения ради красивого макета.

## Визуальная проверка

Отрендери последнюю версию штатным `render_docx.py`. Если LibreOffice недоступен, допустим скрытый отдельный Microsoft Word: отключи макросы, открой read-only, экспортируй PDF, закрой без сохранения и заверши только созданный экземпляр. Не закрывай окна пользователя и восстанови изменённые опции приложения.

На Windows с установленным Word используй готовый [экспортёр](../scripts/render_word.ps1): `render_word.ps1 -InputPath <КП.docx> -OutputPath <новый-КП.pdf>`. Он уже открывает файл read-only, отключает макросы и восстанавливает опцию печати фона.

Посмотри все страницы на контактном листе и отдельно титул, плотные таблицы, графики и последнюю страницу. Проверь обрезку, одиночные заголовки, разрывы строк таблицы, URL, подписи, пустые страницы и чужие данные. Сравни типографику, плотность, шапки таблиц и выводы с выбранным образцом. После правки проверь обновлённые страницы. При недоступном рендере явно укажи, что визуальная проверка не выполнена.
