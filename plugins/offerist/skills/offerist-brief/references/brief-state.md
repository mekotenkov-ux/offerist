# Рабочее состояние брифа

Храни данные текущего клиента вне папки плагина. Используй существующую папку проекта/запуска, иначе `.offerist/briefs/<client_id>/` в рабочем каталоге. Не добавляй реальные клиентские данные в дистрибутив навыка.

Достаточно одного `brief.md` с разделами ниже. Письмо клиенту или повестку сохраняй отдельно, если пользователь просит файл либо они нужны для продолжения. Не создавай пустые файлы каждого будущего режима.

## Шапка

- `client_id`, клиент/компания/сайт; `agency_id`/`run_id`, если уже определены.
- Текущая стадия 1/2/3 и последний режим.
- Дата обновления; статус `draft_for_client`, `awaiting_confirmation` или `confirmed` с источником.
- Источники: файл/сообщение/дата/автор либо URL и дата просмотра.

## Факты и неизвестное

| Поле | Значение | Статус | Источник |
|---|---|---|---|
| Контакты и роль в решении | известное либо «неизвестно» | client_statement / confirmed / unknown | конкретный источник |
| Задачи, KPI, база и срок | известное либо «не согласовано» | client_statement / confirmed / unknown | конкретный источник |
| Приоритеты и регионы | известное либо «неизвестно» | client_statement / confirmed / unknown | конкретный источник |
| ЦА, УТП, конкуренты | известное либо «неизвестно» | client_statement / observation / unknown | конкретный источник |
| Прошлый опыт и текущее измерение | известное либо «неизвестно» | client_statement / observation / unknown | конкретный источник |
| CMS, изменения, ресурсы и согласования | известное либо «неизвестно» | client_statement / confirmed / unknown | конкретный источник |
| Бюджетные ожидания и требования | известное либо «неизвестно» | client_statement / confirmed / unknown | конкретный источник |
| GEO для текущего проекта | yes / no / undecided | confirmed / unknown | конкретный источник |

`client_statement` означает «клиент сообщил», а не независимую проверку реального трафика/продаж. Предложения менеджера и исследовательские гипотезы хранить отдельно, не в подтверждённых фактах. Расширяй таблицу только под реальные данные.

## Доступы и материалы

Система/материал → применимость → `granted` / `requested` / `missing` / `unknown` / `not_applicable` → подтверждённый объект и уровень прав, если известны → цель → источник/дата. Для реальной проверки API отдельно отметь результат проверки; сообщение «доступ выдал» ещё не подтверждает работоспособность API. Секреты не сохраняй.

## Диалог и дальнейшие действия

- Закрытые вопросы и их источники; открытые вопросы в порядке важности.
- Реальные договорённости: действие, согласованная сторона, срок или «не согласован», источник.
- Предлагаемые менеджером действия отдельно, до согласования.
- Наблюдения по сайту/рынку с источниками; гипотезы с условиями проверки.
- Исправленные существенные значения: прежнее → актуальное → источник изменения.
- Для стадии 3: чек-лист того, что клиенту нужно объяснить и доказать в КП.

Перед обновлением прочитай существующий файл. Сохрани известные данные и ссылки; не меняй чужой проект. Если сохранение недоступно, выдай эти разделы кратко в чате как переносимый контекст. Клиентское письмо должно оставаться самостоятельным и не содержать эту служебную структуру.
