# Карта спроса и страниц

Найди необходимые типы **до сопоставления с текущей структурой**: пользовательская задача и интент → подходящий тип/предложение → peer примеры → наши возможные URL → самостоятельность/бизнес-применимость → решение. Набор типов открытый: не ограничивайся категориями, которые уже есть на сайте. В итоговом GAP присутствует объединение текущих и найденных по спросу типов, включая current=0. Если сайт почти пустой, это не означает, что потребности в посадочных нет.

Каждый `create_candidate` связывается с проверенными `missing_intent_ids` и явным `landing_job_id`. Несколько кластеров и интентов могут обосновать одну страницу: считай `supported_missing_intent_count` отдельно от утверждённых задач создания страниц (`page_plan.approved_new_pages` и `landing_jobs` с `disposition:create`). Пока решение открыто, page-plan числа `null` и стадия partial. Один будущий `published_type_id` может покрывать sourced задания других `task_type_ids` через явный `integrated_in_job` с причиной и доказательством, без второй страницы; не утверждай интеграцию по одному сходству тем. Мотивированное `no_new_page` указывает существующие покрывающие URL; `rejected` сохраняет причину и источник бизнес-решения. Неразобранный кандидат/вопрос остаётся partial. Исходные связи и решения передавай в `site_gap.py`; число интентов не является числом страниц для сметы.

Для всего объединённого набора типов принять [поблочный GAP](../offerist-block-gap/SKILL.md) и [текстовый БАР](../offerist-text/SKILL.md). Их пропуск нельзя компенсировать таблицей URL/позиций. Проверка неизвестного остатка и решения по нужным новым страницам идут в начале проекта; не переносить базовый discovery на 4–6 месяц.

Различай **полный реестр**, **охват проверки существующих страниц**, **охват конкурентного спроса** и **охват рангов**. Обнаружить все URL недостаточно для полного GAP: `unknown`-действия не означают «работа не нужна». Перед числом improve/create укажи в основном КП «проверено X/Y страниц; Z непроверены» и число/статус проверенных кластеров спроса; по типам добавь непроверенные. Пока остаются непроверенные части, это подтверждённый минимум работ, а не весь необходимый объём. Не выдавай честный неизвестный хвост за выполненное исследование.

По всей доступной выгрузке собственных и конкурентных запросов составь реестр кластеров: назначение/тип → наши URL → peer URL → covered/create_candidate/rejected/needs_business_answer/unknown с источником и основанием. Не ограничивай спрос пересечением запросов, где уже ранжируются все сайты: так теряются отсутствующие темы. Кластеризация всей доступной базы не требует покупать новые отчёты. У действующих страниц обоснуй keep так же, как improve; массовый keep по отсутствию замечаний запрещён. По неподтверждённым услугам/странам дай отдельные кандидаты и конкретный вопрос владельцу, не выдумывай факт услуги.

Перед объёмами проверь [качество интентов и пригодность посадочных](references/semantic-quality.md). `covered` нельзя выводить только из наличия слова, статьи или главной. Сохраняй отдельно наличие URL, соответствие интенту и достаточность посадочной; информационная инструкция не закрывает автоматически коммерческую потребность. Отдельно разбирай аномальные фразы и другой объект услуги, не наследуй всем строкам интент первого запроса кластера.

Позиции из полного доступного отчёта агрегируй по canonical URL и фактическим типам с весами/датами/порогом; основной GAP показывает ранг страниц по типам и долю URL с наблюдением. Небольшая общая SERP-когорта — дополнительная проверка сопоставимости, она не заменяет анализ доступной базы. Не оставляй доступную полную выгрузку неиспользованной, ссылаясь на недоступность другого провайдера.

Работай как специалист стадии для seller. Получи полный доступный инвентарь сайта: crawl, sitemap, CMS, индексные и органические посадочные, затем сведи дубли и канонические URL. Зафиксируй источники, границы охвата и неизвестные страницы. 12 URL из выдачи или topN отчёта — выборка, не весь сайт. Цель — обследовать каждую обнаруженную страницу, пометив непроверенное как `unknown`; отсутствие позиции не означает отсутствие страницы.

Разметь отдельно назначение (`commercial`, `informational`/`info`, `mixed`, `other`, `unknown`) и тип каждой страницы (`service`, `category`, `product`, `city`, `info` и т. п.; непроверенное — `unknown`). Для каждой существующей канонической страницы выбери одно действие: `keep`, `optimize`, `rework`, `unknown`. `rework` нужен при неверном интенте, шаблоне или каннибализации; `optimize` — когда подходящую страницу можно усилить. Решение `improve` по типу означает хотя бы один конкретный URL с `optimize`/`rework`; другие URL этого типа могут обоснованно остаться `keep`. Если работы нет ни по одному URL и нет утверждённого создания, решение существующего типа — `keep`. Новые страницы считай по утверждённым уникальным `landing_jobs`, а не по числу интентов: сначала проверь существующие URL, пересечение запросов, услугу и город. Разрыв числа URL с конкурентом — ориентир масштаба, не план создания.

Отдельно от действия/единицы работы укажи source-bound плановый маршрут каждого текущего canonical URL: сохранить, снять с 410, слить редиректом в явно сохраняемый canonical или утверждённую новую страницу либо оставить вопрос pending. Для утверждённого создания назови отдельный плановый canonical адрес. Один URL может иметь работу по диагностике или перенастройке и при этом не войти в будущий опубликованный набор; одна задача создания не заменяет проверку маршрутов остальных страниц. Если хотя бы один маршрут или новый адрес не решён, не называй валовую сумму текущих URL и create jobs будущим числом страниц. План после внедрения требует отдельной проверки фактических URL.

Сопоставь с конкурентами в одинаковом коммерческом/продуктовом и региональном срезе: полные доступные числа страниц, охват, типы, ранжирующиеся URL и ссылки. Не смешивай crawl, индекс и ranking URLs. Позиции GSC считай по показам из исходных строк; SERP-съёмы — отдельно с указанным весом и правилами для отсутствия в topN. Среднее средних без весов запрещено. Если ранги неизвестны, структурная оценка всего сайта всё равно может быть полной, а оценка видимости остаётся частичной.

Передай seller короткую таблицу `тип/назначение → текущие страницы → среднее/медиана страниц релевантных конкурентов и охват → средняя позиция/источник/вес → improve/create/подтверждённая цель → основание`, итоговые числа и машиночитаемую детализацию по URL/интентам. Передай все доступные собственные и peer строки ранга с query_id, доменом, URL, позицией и срезом, связав их с сохранёнными исходными строками. Для рангового разреза тип страницы определяется физическим наблюдаемым ranking URL; при старом собственном URL сохрани отдельно его подтверждённый исходный шаблон и тип текущего canonical URL для подсчёта инвентаря. Тип спроса запроса хранится отдельно. Наблюдаемые средние и охват отделяй от строгой парной дельты, которая остаётся null при неизвестных или разных гранях среза. Укажи статус отдельно для охвата инвентаря, конкурентных типов, рангов и ссылок, плюс неизвестное. Для плана 3/6/12 месяцев дай обоснованные объёмы работ и зависимости, а не стратегию, обещание роста или цену. Правила и входной контракт — [карта страниц](references/page-map.md). При необходимости используй `scripts/site_gap.py` для воспроизводимого подсчёта.

Соблюдай [общий контракт стадий](../offerist/references/stages.md).
