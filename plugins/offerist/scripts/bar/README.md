# Офлайн БАР для Оффериста

`cli.mjs` запускает оригинальный `analyzePayload` БАР в Node.js `>=22.13.0`. Готовый runtime состоит из файлов этой папки `adapter.mjs`, `cli.mjs`, `core.bundle.cjs`, `manifest.json` и `../../assets/bar/dicts/`. Он не требует npm install, Next.js, Vinext, FAR checkout или сетевых сервисов. Исходный БАР зафиксирован на commit `c99a55f9369a394cbc98a38e6234620313258a11`; сверяйте `manifest.json` при обновлении.

```powershell
node plugins/offerist/scripts/bar/cli.mjs --input C:\path\input.json --out C:\path\bar-report.json
```

Вход JSON: `page_type`, `intent`, `queries` (массив непустых ключей), `serp_query?`, `language?`, `search?`, `own_page?`, `peers[]`. БАР принимает максимум 20 уникальных ключей до 160 символов каждый; превышение явно отклоняется, включая ключи, разделённые запятой, `;` или новой строкой внутри одного элемента массива. Каждая страница содержит `page_type`, `intent`, `text` (минимум 80 символов для БАР), а также опционально `name`, `url`, `title`, `position`. Все peers должны совпадать с заданными `page_type` и `intent`; страницы разных типов или интентов отклоняются. Адекватность выбранного интента и конкурентов проверяется исследовательским этапом, а не этим валидатором. URL сохраняется как метаданные: сеть для получения страницы не используется. `stop_words?` и `stop_phrases?` передаются как пользовательские фильтры БАР.

Если `own_page.text` присутствует, ответ имеет `mode=own_vs_peers`, `reference_role=own`, `own_score` и полный оригинальный `report` БАР. Один **содержательно сопоставимый** peer здесь допустим: реальная своя страница сравнивается направленно с названной peer-страницей, а `coverage.confidence=low`. Квартили единственного peer совпадают, не образуют диапазон популяционного benchmark; из такого результата нельзя выводить объём работ или KPI. Если сопоставимого peer нет, адаптер возвращает `insufficient_peers`, а этап остаётся blocked/partial до получения источника. Совпадение JSON-ярлыков `page_type`/`intent` — лишь структурное условие: пригодность текстов и поисковой задачи проверяется отдельно.

При отсутствии своей страницы берётся реальная peer reference с наилучшей указанной позицией (или первая по входному порядку), сравнивается с остальными peers и возвращается `mode=peer_only`, `reference_role=peer`, `own_score=null`. Поле `peer_benchmark` содержит метрики именно этой конкурентной страницы, интервалы по другим peers и требования к будущему тексту; клиентский балл не создаётся. Для peer-only нужны как минимум две peer страницы, иначе статус `insufficient_peers` без метрик: одна страница не может быть одновременно reference и независимым peer для сравнения. `coverage` отдельно показывает `comparable_peer_pages`, `analyzed_peer_pages`, `excluded_peer_pages` (разность первых двух), `warning_count`, язык и доступные зоны. В peer-only режиме выбранная reference не входит в `comparable_peer_pages`. Ни режим с одним peer, ни `insufficient_peers` не удаляют типы или слабые URL из реестра покрытия. Перед первым анализом адаптер сверяет SHA-256 фактического bundle и всех 10 словарей с поставляемым `manifest.json`; при расхождении прекращает работу. Provenance в ответе отражает только прошедшие эту проверку файлы.

Для реального публичного текста с артефактами извлечения адаптер передаёт ядру отдельную анализируемую копию. Непрерывные буквенно-цифровые токены длиннее 80 UTF-16 единиц исключаются из этой копии: исходный БАР строит н-граммы до трёх слов, а ключ snapshot ограничен 256 символами. Пример из сохранённого корпуса — слитный список языков переводческого виджета длиной 217 символов. Исходный вход не изменяется и не укорачивается молча. `preparation.pages[]` содержит SHA-256 исходного и анализируемого текста, число/длину и SHA-256 исключённых токенов по каждой странице; `preparation.warnings` сообщает о корректировке. `provenance.adapter_sha256` идентифицирует эту обёртку, а `bundle_sha256` остаётся хешем исходного БАР. Если после исключения материала недостаточно, анализ завершается ошибкой без балла. Метрики в таком ответе относятся только к явно указанному анализируемому тексту.

Офлайн `text`-вход БАР позволяет сравнить только зоны `all` и `text`; `title`, `h1`, H2–H6 и `anchors` здесь недоступны. Зональное ТЗ требует отдельной проверки HTML/URL-режима в исходном БАР. Метрики отражают текстовую близость к выбранным peers и не доказывают будущие позиции, трафик или заявки. При `peer_only` ориентиры привязаны к длине реальной peer reference; это стартовые требования к черновику, не целевые значения для ещё отсутствующей страницы. Повторный расчёт по snapshot и поиск выдачи этому CLI не доступны.

Исходные файлы `source/semantic-analysis.ts`, `source/language-support.ts`, `source/phrase-similarity.ts` скопированы без изменения. `source/russian-morphology.ts` адаптирует только Vite-загрузку словарей к поставляемой Node-папке; словарь Az.Morph и выбор леммы не меняются. `build.mjs` воспроизводит bundle из этих исходников и уже установленных точных версий зависимостей:

```powershell
node plugins/offerist/scripts/bar/build.mjs --deps C:\path\to\node_modules
```

Builder проверяет хеши исходников и словарей, версии зависимостей, отсутствие внешних JS-импортов и записывает SHA bundle в `manifest.json`. Он нужен только для обновления поставки. В bundle входят JS пакеты `az 0.2.3`, `snowball-stemmers 0.6.0`, `stopword 3.1.5`; `esbuild 0.28.1` — сборочная зависимость. Лицензии и атрибуция находятся в `../../assets/bar/licenses/`: исходный БАР MIT, Az.js MIT по package metadata, Snowball ISC по package metadata, stopword MIT, словарь OpenCorpora CC BY-SA 3.0. Сведения об Az/Snowball отражают metadata установленных npm-пакетов; отдельные license-файлы в этих пакетах отсутствовали.

Проверка: `node --test tests/production/development-cycle-20261003/bar/bar.test.mjs` из корня workspace. Она включает русский анализ, peer-only режим, регрессию на публичном входе с некорректной н-граммой, отказ при недостатке текста после исключения артефактов, запрет смешения типов/интентов и переполнения ключей, отсутствие сетевых вызовов, подмену bundle/словаря, хеши и запуск в отдельном временном checkout с пробелами без `node_modules`.
