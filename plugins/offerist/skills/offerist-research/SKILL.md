# Анализ конкурентов

Используй [компактный контракт анализа](references/autonomous-analysis.md). Начни с брифа, приоритетных продуктов и региона. Подбери сильных конкурентов по релевантности предложения и доступным метрикам Keys.so, Ahrefs либо другого подключённого источника. Присланных клиентом проверь на сопоставимость. Прямые компании, агрегаторы и информационные площадки сравнивай в разных группах. Не трать время на домены, которые не меняют вывод.

## Сравнение

До вывода об отсутствии инструментов выполни [обнаружение подключений](../../docs/connectors.md), включая XMLRiver вне реестра. Используй общий кэш проекта. Ahrefs ограничивай небольшими агрегатами и разрешённым бюджетом; массовая выгрузка ссылок по умолчанию не нужна. Keys.so собирай с пагинацией выбранного отчёта. Новое полное семантическое ядро собирай только после согласия пользователя.

Верни таблицу клиента и сильных конкурентов с доступными показателями страниц, ссылок, уникальных доноров, оценки трафика Google, оценки трафика Яндекса, числа запросов в ТОП 3, ТОП 5 и ТОП 10. У каждого показателя должны быть источник, дата базы, система, регион, определение и охват. Пороги ТОП 3/5/10 вложенные, их нельзя складывать. Недоступная метрика остаётся пустой с причиной, а не нулём. Если источник сообщает только ранжирующиеся URL, не называй их страницами с ненулевым трафиком. У Keys.so `pagesinindex` — URL в ТОП 50, `vis` — оценка органических пользователей в сутки; это не месячные визиты. Для другого источника меняй подпись и единицу по его определению, не подгоняй значение под старый заголовок таблицы.

Ответ «отчёт готовится», включая HTTP 202 или `code=202`, не является готовым отчётом и не должен попадать в успешный кэш. Повторяй получение только в пределах общего бюджета и лимитов источника. При исчерпании бюджета сохрани реальный статус подготовки, а не нулевые метрики.

Для российских проектов Яндекс и Google обязательны как отдельные срезы. `msk` и `gru` Keys.so относятся к Москве, а не ко всей России; дату получения не выдавай за дату выдачи. Несопоставимые периоды и базы не объединяй в один рейтинг. Оценочный трафик не равен кликам GSC или визитам Метрики.

## Страницы конкурентов

Выгрузи доступные URL с поисковой видимостью и сохрани сортировку по доступной наблюдаемой метрике в рабочем анализе. Покажи тип, назначение, запросы, позицию или оценочный трафик и источник. Назови критерий сортировки. Передай [GAP аналитику](../offerist-gap/SKILL.md) все строки выбранного среза, а не только красивые примеры. Полный обход конкурентов для КП не нужен.

В клиентский блок II. передавай `competitor_examples`, а не обязательный рейтинг «Видимые посадочные конкурентов». Для каждого выбранного примера нужны ссылка на конкретную страницу, наблюдаемый приём или содержание, его значение для задачи клиента и наше применимое решение. Покажи, например, как конкурент объясняет условия услуги, закрывает отдельный спрос или помогает выбрать вариант. Само наличие URL в ТОП 10 не доказывает полезность его копирования. При наличии снимка передай читаемый реальный фрагмент и подпись с объяснением; не выдавай нарисованный пример за страницу конкурента.

Если есть только сводные количества страниц, передай диапазон грубого потенциала с ограничением. Это гипотеза масштаба, которую нельзя считать подтверждённым заказом на столько же страниц. Для отбора механик доступны [обратный разбор](references/reverse-engineering.md) и [метод исследования](references/method.md); они не требуют отдельного регламентного конвейера.

## Результат

Сохрани `competitors.md`, сводную таблицу, рабочий список URL и исходные ответы. Передай подводку от «Мы» с названием проверенного рынка и ссылками на анализ/таблицу для начала раздела. Дай вывод о положении клиента, объясни разрыв в понятных единицах, добавь предметные примеры и наши решения. Статус покрытия и существенные границы нужны рядом с соответствующим выводом, а не отдельным хвостом «Источники». Ссылочный специалист использует те же агрегаты без повторного платного запроса. Не обещай повторить чужой рост и не пиши целое КП.
