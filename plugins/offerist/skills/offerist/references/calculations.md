# Минимальные проверяемые расчёты

Команда `calculate --input dataset.json` принимает один JSON; все блоки необязательны. Пропущенные значения возвращаются как `null` или явная ошибка, не ноль.

```json
{
  "positions": [{"position": 8, "impressions": 100}, {"position": 20, "impressions": 50}],
  "pages": [{"url": "https://example.org/a", "action": "optimize"}, {"url": "https://example.org/b", "action": "unknown"}],
  "missing_clusters": [{"id": "new-1", "intent": "Отдельный подтверждённый спрос"}],
  "page_counts": [{"domain": "example.org", "count": 100, "definition": "ranking_urls", "source": "same-tool", "period": "2026-08", "engine": "google", "region": "RU", "device": "desktop", "segment": "commercial"}, {"domain": "peer.example", "count": 160, "definition": "ranking_urls", "source": "same-tool", "period": "2026-08", "engine": "google", "region": "RU", "device": "desktop", "segment": "commercial"}],
  "continuation": {"eligible_visits": 1000, "continued_visits": 420, "definition": "Сессия с переходом на другую содержательную страницу", "same_cohort": true}
}
```

Позиция = сумма(position × impressions) / сумма(impressions) для сопоставимой выборки. Это агрегат GSC-показов, не среднее по SERP-съёмам; альтернативную методику явно называй. Нулевые показы не дают позиции. Смешанные даты/устройства/системы предварительно разделяй.

Действие по существующей посадочной одно: `keep`, `optimize`, `rework`, `unknown`; нижний регистр host и удаления fragment недостаточно для полного canonical mapping — заранее сверяй редиректы и canonical. CLI обнаруживает повторные URL и не меняет параметры/регистр path автоматически. Доли = count / число обследованных существующих URL, включая unknown. Создание = отдельное количество уникальных отсутствующих intent-кластеров, не процент от URL существующего сайта. Большой разрыв числа страниц конкурента сам по себе не доказывает необходимость копировать объём.

Для таблицы GAP вручную своди тот же инвентарь по типам страниц: `наши всего = keep + optimize + rework + unknown` среди уникальных существующих canonical URL. В тексте `revise` означает CLI-действие `rework`; не складывай эти ярлыки как две группы. `create` считай отдельно по уникальным отсутствующим кластерам и не добавляй к текущему числу URL. Общая сумма по типам должна сходиться с инвентарём либо явно объяснять нераспределённые/неизученные страницы. Сравнение с конкурентами и позиции делай только для сопоставимых определений и с указанным охватом; CLI сам не подтверждает полноту сайта.

План на 3, 6 и 12 месяцев обозначай как накопительный или добавочный. Для накопительного плана каждый следующий горизонт не меньше предыдущего, а итоговый объём `create/optimize/rework` не превышает согласованную потребность без объяснённого нового спроса; для добавочного плана сумма партий равна общему объёму. Сверяй выпуск с мощностью команды, владельцем публикации и временем приёмки. Это расчёт контролируемых работ. Численные позиции, трафик, заявки и AI-цитирование оформляй лишь как условные сценарии с базой и предпосылками; этот калькулятор их не прогнозирует.

Сравнение объёмов только внутри одинакового определения/источника/периода/поиска/региона/устройства/сегмента. CLI возвращает абсолютную дельту к первой записи и относительную дельту при ненулевой базе. Это объём базы инструмента, если definition=ranking_urls; нельзя подписывать как весь индекс.

Ссылочный GAP считай отдельно и только для одинаковой единицы (например, уникальные ссылающиеся домены), окна, индекса, фильтров и источника. Укажи наши и конкурентные числа, абсолютный разрыв и применимый план получения ссылок; разрыв не равен обязательной закупке. Если данных нет, поставь `неизвестно`, а не ноль.

Продолжившие изучение = continued_visits / eligible_visits в одной когорте. Определи содержательный переход и фильтры до расчёта; второе событие не обязательно переход. GA4 engagement и 1−bounceRate не заменяют этот показатель. При отсутствии нужных событий — неизвестно, предложить настройку измерения.
