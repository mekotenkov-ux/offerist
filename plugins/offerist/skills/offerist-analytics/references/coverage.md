# Полнота и информационный / коммерческий трафик

Полный сбор доступных строк — стандарт. Размер страницы API служит пагинации, а не ограничивает анализ. Не ограничивай сбор 100 строками, фиксированным числом отчётов, URL или конкурентов. Предпросмотр допустим по явному запросу; назови его неполным. Не переноси ограничения старых тестовых прогонов в новый проект.

На каждую выгрузку сохрани property/counter, период, часовой пояс, фильтры, атрибуцию, измерения, метрики, страницы/offset, число строк и уникальных URL, total_rows, источник итогов, семплирование, ограничения провайдера и статус пагинации. Различай: `pagination_complete` — получены все доступные страницы ответа; `site_complete` — подтверждён охват выбранной когорты сайта. Кэш без такого описания не доказывает полноту. Ошибка следующей страницы, повтор страницы, изменение total или прерванный сбор дают partial; сохрани успешно полученную часть.

У GSC даже исчерпанная пагинация не гарантирует все строки сайта. Итоги свойства, постраничные и запросные суммы могут различаться. Не оценивай долю всего информационного/коммерческого трафика по topN или сумме ограниченных запросов. Для Метрики сверь суммы аддитивных визитов и визитов с целью с итогами того же среза; показывай семплирование. Пользователи и число достижений цели не заменяют эти метрики. Popular queries Вебмастера — ограниченное представление провайдера, а не весь спрос.

Разметь URL по проверенному назначению: `informational`, `commercial`, `mixed`, `other`, `unknown`. Префикс /blog/ или /services/ — подсказка; проверь назначение страницы и запросы. Неизвестное оставь неизвестным. Не относись к смешанной странице как к чистой коммерции. Сохрани основания и одну версию разметки для обоих периодов.

Сначала собери все посадочные органики и отдельно суммы сайта. Затем покажи для каждой группы: уникальные URL, визиты/клики, долю только при подтверждённой полноте, настроенные goal visits и конверсию, изменение в сопоставимых периодах. Цели Метрики — не подтверждённые заявки CRM. Рост статей без коммерческих обращений не доказывает рост продаж. Не усредняй CTR или конверсии строк: дели сумму числителей на сумму знаменателей. URL × устройство — несколько строк одной страницы; одинаковый исходный grain нельзя считать дважды. Отсутствие URL в неполном отчёте не означает 0.

Для GAP передай машиночитаемый список `canonical_url, purpose, purpose_basis, organic_clicks/visits, impressions, observed_rank, rank_weight, period, source, scope` и отдельный флаг полноты. Ранг GSC вычисляется по исходным строкам как `Σ(position × impressions) / Σ(impressions)`; уже агрегированные средние без их показов не объединяй. Отсутствие ранга оставь `null`, не 0. Список GSC может быть ограничен провайдером даже при завершённой пагинации; структурная инвентаризация сайта может быть полной независимо от этого. Сверь его с crawl/sitemap/CMS и отметь страницы без органического наблюдения как неизвестные по рангу.

Для повторяемого расчёта используй `scripts/traffic_segments.py` в корне плагина:

```shell
python scripts/traffic_segments.py --input segment-input.json --out segment-report.json
```

Вход: `source: metrika|gsc`, `cohort: {property, filters, timezone, attribution}`, `classifications: [{url, group, basis}]`, `periods: [{id, coverage, totals, rows}]`. `coverage` содержит четыре строгих boolean: `pagination_complete`, `site_complete`, `provider_limited`, `sampled`. Строка содержит точный `url`, при необходимости `dimensions` исходного grain и аддитивные `visits, goal_visits` либо `clicks, impressions`. `totals` содержит эти же метрики из отдельного итога источника. Null сохраняется как неизвестное; суммы и ставки с неизвестным числителем не выдумываются. Расчёт не определяет интент автоматически и не превращает данные GSC в полную картину сайта.

Расчёт возвращает `metric_complete` и `metric_comparable` отдельно для каждой метрики: известную динамику визитов можно показать даже при неизвестных целях. `metric_reconciliation` различает `reconciled`, `unavailable` и `mismatch`; отсутствие цели не означает расхождение суммы визитов. `purpose_classification_complete` подтверждает разметку всех собранных входных URL. Старое поле `intent_complete` — совместимый псевдоним этой полноты, а не измерение поискового запроса посетителя. Текущее назначение страницы, перенесённое на прежние периоды, не доказывает её прошлое содержание. Неизвестные целевые визиты не превращаются в нули.

Перед объявлением постраничных целей недоступными проверь уже сохранённые отчёты каждой цели. При совпадении счётчика, периода, фильтров, атрибуции и точного URL × device grain их можно пересчитать без нового API-запроса. Обрабатывай отдельную цель отдельным входом с явным `cohort.goal_id`; сверь строки и знаменатель с базовым отчётом и итогом этой цели. Несколько целей могут сработать в одном визите: их сумма не является объединением целевых визитов или уникальными заявками. Если по одной цели есть полный отчёт, а по другой только итог, показывай эту разницу поцелево.

В клиентский текст выведи таблицу групп и график с понятным выводом: что растёт, какие страницы приносят целевые визиты, что подрядчик будет менять и как проверять результат. Подробную разметку и охват сохрани в приложении. Если данных недостаточно, объясни конкретный пробел и способ измерения, не имитируй полный анализ.
